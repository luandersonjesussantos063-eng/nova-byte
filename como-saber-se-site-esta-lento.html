Como saber se meu site está lento?

RESPOSTA CURTA

Um site pode ser considerado lento quando demora para começar a responder ou quando conteúdo importante leva vários segundos para aparecer e estabilizar. Imagens pesadas, scripts excessivos, servidor lento e código mal otimizado são causas comuns.

O que observar além do tempo total?

Tempo de resposta do servidor, Largest Contentful Paint, mudanças de layout, bloqueios de JavaScript e sensação de resposta ao toque são indicadores úteis.

Imagens são um problema comum?

Sim. Imagens muito grandes, sem compressão ou em formatos antigos podem representar grande parte do peso da página.

Velocidade afeta vendas?

Pode afetar. Quanto mais demorada e instável é a experiência, maior a chance de o visitante desistir antes de entrar em contato ou concluir uma ação.

Meça a URL exata e registre as condições

  1. Abra o PageSpeed Insights e informe a página que o visitante realmente acessa, não apenas a página inicial.
  2. Compare as abas de celular e computador. Guarde a data, a URL e quais recursos aparecem como problemas. Uma execução isolada pode variar.
  3. Separe dados de usuários reais de uma simulação de laboratório. Quando não houver dados de campo suficientes, isso não prova que o site seja rápido ou lento.
  4. Repita o caminho principal em um celular: abrir o menu, selecionar um serviço, preencher o formulário e voltar. Rapidez de carregamento e resposta à interação são problemas diferentes.

O que cada indicador ajuda a investigar

LCP acompanha a apresentação do conteúdo principal; imagem grande, resposta do servidor e fontes podem atrasá-lo. INP acompanha a resposta às interações; scripts longos podem prejudicar o toque. CLS indica deslocamentos inesperados; imagens sem dimensões e elementos inseridos acima do conteúdo são causas a verificar. Consulte as definições e faixas atuais em Core Web Vitals.

Corrija uma causa e teste o comportamento completo

Se a foto principal for o maior recurso, reduza suas dimensões para o uso real e avalie um formato eficiente. Não aplique carregamento tardio indiscriminadamente à imagem que aparece primeiro. Reserve largura e altura para evitar deslocamentos. Se o gargalo for JavaScript, identifique qual funcionalidade depende dele antes de removê-lo.

Depois da mudança, confira se imagens continuam legíveis, se o menu funciona e se o formulário entrega a mensagem. Uma nota maior não compensa quebrar uma função. Não registramos nesta página uma pontuação medida do seu site; esse resultado exige executar o diagnóstico na URL publicada. Para uma revisão mais ampla, consulte o roteiro de auditoria.
