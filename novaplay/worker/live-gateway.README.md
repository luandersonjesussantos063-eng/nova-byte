# Protected live delivery

`live-gateway.mjs` serves purchased live MPEG-TS and HLS streams over HTTPS. Provider URLs, including account paths, are stored in private server bindings. Existing TS sources use `LIVE_SOURCES` KV; the Pulsando HLS catalog uses gzip-compressed `PULSE_CATALOG_<hex>_<part>` secret bindings, sharded by channel ID. Never commit playlists, KV exports or provider credentials.

Viewer requests must carry a Supabase session. The Worker reads the corresponding channel through the viewer's existing RLS policies and requires the stored playback URL to exactly match this gateway and channel ID. Approved viewers can read published channels; administrators can test their drafts. It forwards no viewer authorization to the provider, follows only validated public HTTP(S) redirects, streams the response body and returns generic upstream errors.

Bind `LIVE_SOURCES` to the `nplay-live-sources` KV namespace. Keep `PROBE_KEY` as a Worker secret for scoped diagnostics; the probe never returns provider bodies or URLs. Enable `observability.redact_query_string`, disable invocation logging and tracing, and preserve secret bindings on upload. The gateway does not transcode. `hls-relay.mjs` rewrites HLS manifests, keys, audio and video resources to authenticated encrypted locators. `HLS_MEDIA_KEY` is a private AES-GCM key; locators are bound to the channel ID and remain subject to viewer RLS. Media responses stream without buffering, while manifests and catalog shards have explicit size limits. Protected streams are excluded from automatic previews.

The ADM signal test uses the current session only on the owned gateway origin. Tokens are never persisted in channel metadata or sent to casting receivers. A channel is published through the existing ADM test after image and at least two seconds of moving video are confirmed. Imports remain drafts; importing metadata does not confirm playback.
